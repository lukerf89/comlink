Build the local work voice loop first, then capture meetings for agents.

This outline turns the July 3, 2026 product spec into a sequencing view: what should come first for a work-focused, local-only CLI; when meeting transcripts should enter the roadmap; where timing is most uncertain; and which decisions should be settled before writing a full implementation plan.

Implementation stance

Optimize for work text and meeting transcripts, not a broad transcription app.

The useful product is a local CLI that starts with retained voice memos, then adds personalized work modes for coding prompts, Outlook replies, Slack replies, and memos. The plan should make output agent-readable before meeting capture, then prove in-person meetings before Zoom and Teams audio.

Keep

Terminal-first Rust CLI

It keeps interface design minimal while making the same commands usable by a person or an agent.

Keep

whisper.cpp first

Early builds can require local `whisper.cpp` and FFmpeg installs, with `doctor` explaining missing dependencies.

Keep

Copy before paste

Clipboard delivery fits the first work use cases and avoids over-investing in OS automation too early.

Move earlier

Basic memo first

Ship retained voice memos with no style guide before personalized work modes.

Move earlier

Agent-readable output

JSON/JSONL should include raw text, final text, segments, timestamps, mode, source metadata, and context metadata.

Move earlier

Meetings after agent CLI

Ship MacBook-mic meeting transcripts after the JSON contract, then add Zoom and Teams system audio.

Primary use cases

The build should support personal work text and meeting transcripts.

These are the acceptance-test scenarios for the first implementation plan. Voice memos come first because they prove the local loop and create benchmark data. Personalized work modes and meeting capture follow after the output contract is stable.

Mode

Voice memos

Save retained raw and clean transcripts with timestamps, segments, metadata, a session reference, and optional copy.

Mode

Coding prompts

Use a style profile and optional local rewrite to turn rough intent into clear agentic coding prompts.

Mode

Email replies

Produce Outlook-ready replies guided by local examples, without inventing facts or unsupported commitments.

Mode

Slack replies

Shape concise responses using a local Slack style profile supplied during setup.

Mode

Notes and memos

Capture rough thoughts into dated notes, memos, bullets, or summaries that can be searched or processed later.

Mode

Meeting transcripts

Record in-person meetings first, then Zoom and Teams, producing raw transcript segments with timestamps.

Consumer

AI agents

Expose stable machine-readable output without default action hints, so separate approved agents can do extraction.

Constraint

Offline-capable core

Core functionality must be fully usable without network access. Strict offline enforcement is optional.

Critical path

The system is only as reliable as the voice loop underneath it.

This is the dependency order I would protect. Each downstream feature can be more ambitious only if the earlier stage is observable, testable, and easy to replace without changing the whole product.

Timing outline

Recommended build checkpoints before the full plan.

Timing assumes one experienced engineer, macOS first, local binaries allowed, and no custom UI beyond terminal/daemon indicators. These are planning bands, not commitments.

Rust + Clap skeleton, config path, `transcribe FILE`, system `whisper.cpp`, FFmpeg assumption, `doctor` checks, stdout, JSON envelope, temp file hygiene. Demo: local audio file to text and JSON with no network path. Low, because early builds can require manually installed local dependencies.

4. Demo: a 30-60 minute in-person meeting produces JSONL segments and Markdown after stop. Medium, driven by long-recording stability, chunk stitching, timestamp quality, and benchmark retention.
5. Zoom and Teams audio spike 2-4 days Decide the local system-audio path before committing the full milestone. macOS system audio capture research, Zoom/Teams permission checks, mic vs system source labeling probe, virtual-device dependency decision, local-only diagnostics. Demo: a short Zoom or Teams call captures enough local audio to prove the path or name the dependency. High, because macOS may require a documented local audio driver or virtual device.
6. Zoom and Teams audio v0 7-14 days Online meetings can be captured locally without relying on built-in meeting notes. System audio adapter from spike, mic plus system source handling, source labels, Zoom/Teams acceptance tests, permission diagnostics, timestamped transcript export, no diarization requirement. Demo: a Zoom or Teams call exports agent-readable transcript segments with source metadata. High, because permissions, audio routing, and app behavior are the hardest part of this path.
7. Meeting context enrichment 4-7 days Meeting transcripts carry enough metadata for a work-approved LLM to write notes. Optional meeting title, participant roster, project tags, agenda/context file, source labels where known, context policy in output, export bundle for downstream agents. Demo: a transcript plus context JSON can be handed to an approved agent for structured meeting notes. Medium, with diarization and speaker identity treated as later enhancements unless source labels are enough.
8. Workday surface hardening 5-10 days Clipboard/manual paste is proven across the actual work surfaces. Terminal for agentic coding, Outlook email, Slack, personal memos, copy behavior, formatting fixtures, local dev install docs, optional `listen`/hotkey spike. Demo: copied output works in terminal, Outlook, Slack, and memo capture without active paste. Medium, because active paste can remain deferred but formatting issues will surface here.
9. Pro polish 1-3 weeks Modes and meetings get smarter while preserving local and inspectable behavior. Selected text transform mode, git-aware context, project vocabulary, optional local HTTP/MCP surface, diarization research, searchable transcript library, shareable-version retention policy. Demo: transcript bundles and work outputs both expose explicit allowed context. Medium to high, depending on diarization access, archive UX scope, and distribution expectations.

Plan-shaping principles

Rules I would carry into the full implementation plan.

These are not product copy. They are engineering constraints that should keep the implementation from becoming tangled as the feature surface grows.

1

One pipeline, many commands

`record`, `transcribe`, `batch`, and future `meet` should share the same normalized result schema.

2

Raw text always survives

Every clean, rewrite, or prompt mode should preserve the raw transcript for debugging and trust.

3

Offline must work

Strict enforcement is optional, but core recording, transcription, and output must require no network access.

4

Agents are first-class

Every human-facing command should have stable machine-readable output and predictable exit behavior.

5

Transcript before notes

Comlink should produce timestamped transcript bundles; approved downstream agents can create structured notes.

6

Retain while building

Keep transcripts for benchmarking during build-out; limit raw audio to explicit benchmark settings.

Risk review

Risks that most affect sequencing.

These are the places I would add spikes, acceptance tests, or explicit deferrals in the full implementation plan.

High

Paste and hotkeys

System-wide paste is app-specific. Keep it after copy and after the core work modes are useful.

Medium

VAD quality

Bad VAD harms speed and trust. It needs fixtures for silence, short utterances, noisy rooms, and long meeting chunks.

Medium

Model packaging

The timing changes depending on whether v1 shells out, downloads binaries, or bundles runtime assets.

High

Workplace privacy

The app must work offline, avoid hidden cloud inference, and make local retention visible during build-out.

Medium

Style drift

Style-personalized modes can over-polish. They should use local examples while preserving raw text and intent.

High

System audio capture

Zoom and Teams transcription depends on local system audio capture, permissions, and source separation.

Medium

Speaker context

Knowing who spoke may require manual participant context, source labels, or later diarization. Raw timestamps come first.

Resolved decisions

Locked inputs for the full implementation plan.

These decisions came out of the review sequence and should be treated as the planning baseline unless you change direction before implementation.

Milestone

First demo

`record --mode memo --copy --format json` captures from the MacBook mic, retains a transcript, copies clean text, and emits JSON.

Install

Dependencies

Early builds may require locally installed `whisper.cpp` and FFmpeg. `comlink doctor` should detect and explain missing pieces.

Platform

macOS first

Implementation and acceptance tests are macOS-first. Linux and Windows remain architecture considerations only.

Privacy

Offline core

Strict offline enforcement is optional. Core recording, transcription, style, and export flows must be fully functional offline.

Retention

Build-out transcripts

Keep transcripts by default during build-out for benchmarking. A shareable version can later retain transcripts for a limited number of days.

Retention

Benchmark audio

Audio may be retained only under an explicit benchmark/training setting with local limits and prune/audit visibility.

Meetings

Meeting v0 demo

A 30-60 minute in-person meeting through the MacBook microphone exports timestamped JSONL and readable Markdown after stop.

Meetings

No live transcript UI

Meeting v0 records safely and shows recording/chunk progress, but readable transcript finalization happens after stop.

Meetings

System audio path

Run a Zoom/Teams spike before the full milestone. Avoid a virtual audio driver if possible, but allow a documented local dependency if required.

Modes

Basic before style

Ship basic voice memos without a style guide first. Work modes include style setup because personalization is their main purpose.

Modes

Style setup

Style setup is designed for an AI agent to provide structured examples. Store raw examples and distilled profiles during build-out.

Modes

Local rewrite

Local LLM rewrite lands early as an optional adapter for style-personalized work modes. Core transcription works without it.

Surfaces

First surface tests

Test clipboard/manual paste in terminal for agentic coding, Outlook email, Slack, and personal memos.

Packaging

Local dev install

Use local dev install first, such as `cargo install --path .` or `target/release`, with Homebrew/signing deferred.

Agents

No default hints

Agent output includes raw/final text, segments, timestamps, mode, source metadata, and context metadata. No default action-item hints.

Meetings

Transcript bundles only

Comlink produces high-quality timestamped transcript bundles plus metadata/context. Meeting-note generation happens elsewhere.
