Research synthesis

What the winning products have in common

The best systems are not just ASR. They combine trigger UX, audio boundaries, text cleanup, context, delivery, and history into a coherent loop.

Wispr Flow

Polish through context

  • System-wide hotkey and text insertion
  • App, textbox, and window context improves formatting
  • Dictionary, snippets, styles, history, and usage stats

Lesson: dictation feels magical when context and delivery are reliable.

Superwhisper

Modes as the product primitive

  • Voice processing is separate from AI processing
  • Modes choose model, language, LLM, and instructions
  • Local Whisper and Parakeet options are explicit

Lesson: comlink should make mode selection fast and inspectable.

Aqua Voice

Real-time refinement matters

  • Developer accuracy needs syntax and jargon awareness
  • Writing style rules and dictionary are first-class
  • Screen context can be part of accuracy, not just styling

Lesson: technical terms and code symbols deserve their own mode.

Granola

Meetings are a different lifecycle

  • Explicit start/stop and visible recording state
  • Mic plus system audio is more useful than one stream
  • Notes and transcripts persist even when audio does not

Lesson: meeting mode should be a later dedicated pipeline.

OpenWhispr and VoiceInk

OS helpers are real infrastructure

  • Native helpers handle hotkeys, paste, and monitoring
  • Local models, SQLite, history, dictionary, and modes recur
  • Active app, URL, selection, and clipboard can feed context

Lesson: paste and hotkey belong behind adapters, not ASR.

MacParakeet

Pipeline scheduling is a feature

  • Separate dictation, meeting, file, and URL pipelines
  • Shared mic stream and STT scheduler
  • SQLite library, vocabulary, snippets, transforms

Lesson: background jobs and live dictation should not fight.

Architecture pattern

Separate the voice loop into small, inspectable stages

Each stage should be independently replaceable. That keeps the MVP simple while leaving room for a daemon, faster models, local LLMs, and meeting workflows.

01

Trigger

Foreground command now; global hotkey and push-to-talk in daemon mode later.

02

Capture

Mic input, permissions, level meter, pre-roll, 16 kHz mono WAV normalization.

03

VAD

Silero finds speech regions, trims silence, and blocks empty audio hallucinations.

04

ASR

whisper.cpp by default, with adapters for faster-whisper and Parakeet.

05

Cleanup

Deterministic filler removal, vocabulary, snippets, punctuation, and actions.

06

Context

Explicit CLI flags, cwd, git hints, selected text, and app context only when allowed.

07

Delivery

stdout, JSON, Markdown, clipboard, paste adapter, saved transcript, or API/MCP.

08

Storage

SQLite history, model registry, vocabulary, snippets, modes, logs, and retention.

Core design rule

Deterministic cleanup runs before any LLM rewrite. Raw text is always retained when history is enabled, and LLM failure falls back to clean text with a warning.

Runtime choices

A model stack that starts boring and grows sideways

The practical default is portable local inference first, with specialized engines added by mode and workload rather than forcing every user into a heavy ML stack.

Default whisper.cpp Best MVP runtime: portable, CPU-friendly, easy to shell out to, and simple to package with model files.
VAD Silero Fast speech boundaries, silence trimming, and empty-audio rejection before ASR.
Batch faster-whisper GPU and quantized acceleration for file queues, archives, and server-style work.
Low latency Parakeet Experimental path for supported languages when packaging and licensing are acceptable.
Files and meetings WhisperX Word timestamps, alignment, and diarization, but not an MVP dependency.

Build sequence

Ship usefulness before polish, then add OS depth

The phases keep the MVP local and scriptable before taking on the harder parts: daemon UX, global hotkeys, active paste, app context, and meeting capture.

Phase 0

Research spike

  • comlink transcribe FILE
  • comlink record
  • stdout only, no history
Phase 1

Useful local CLI

  • Model management
  • FFmpeg and Silero VAD
  • Clean mode, vocab, snippets
  • Clipboard and SQLite
Phase 2

Dictation daemon

  • Global hotkey
  • Recording indicator
  • Copy/paste adapter
  • App-specific mode rules
Phase 3

Developer mode

  • Prompt and terminal modes
  • Selected text transforms
  • MCP or local HTTP server
  • Git-aware context
Phase 4

Meeting and file pro

  • WhisperX and diarization
  • System audio adapters
  • Notes and action extraction
  • Searchable transcript library
Guardrails

The product promise is local, predictable, and reversible

These rules should shape implementation and product copy. They are also good tests: a feature that violates them needs explicit opt-in and clear UI.

Privacy

No hidden network path

Offline mode blocks model downloads and LLM HTTP calls. No cloud fallback without an explicit command.

Retention

Audio off by default

Short dictation uses temp audio and deletes it. Transcript history is a visible setting or command choice.

Accuracy

Never ASR silence

VAD and minimum-duration guards prevent Whisper-like hallucinations on empty or noisy clips.

Meaning

LLM rewrite is optional

Local LLMs receive text only, can be skipped with --no-llm, and fall back to deterministic clean text.

Feedback needed

Open questions before implementation hardens

These are the decisions most likely to change architecture, packaging, or early UX.

1. Should the MVP be terminal-first or daemon-first?
Terminal-first gets record, transcribe, model management, and scriptable output working quickly. Daemon-first validates the Wispr-like value sooner, but pulls in hotkeys, permissions, indicators, and paste complexity.
2. Which language should anchor the core?
Rust fits a polished cross-platform daemon and native adapters. Python/Typer fits a fast research spike around ASR and VAD libraries. Go is a pragmatic middle path.
3. What is the default model and install story?
The spec points at whisper.cpp plus small.en as a strong default. We still need a decision on bundled runtime, model download verification, license display, and whether English-only is acceptable initially.
4. Is transcript history on or off by default?
History makes the product useful and debuggable, but the privacy posture is cleaner with retention off until explicitly enabled. A compromise is metadata-only history by default, with transcript retention opt-in.
5. How much context should comlink ever read?
CLI context such as cwd, git branch, and flags is low risk. Selected text, clipboard, app name, URL, and textbox context are valuable but should be explicit, logged, and controlled by mode policy.
6. Should paste be copy-first or active-app-first?
Clipboard copy is reliable and MVP-safe. Active paste is the product magic, but it needs OS-specific adapters and failure handling. The spec recommends copy first, paste in daemon mode.
7. How early should terminal/coding mode ship?
For this project, developer dictation feels like a differentiator. It may deserve to move from Phase 3 into Phase 1 as a deterministic mode that preserves symbols, filenames, commands, URLs, camelCase, and snake_case.
8. What platforms matter first?
macOS is the easiest place to start for local CLI plus clipboard and eventual accessibility paste. Linux and Windows change hotkey, paste, audio, and packaging constraints enough that they should be explicit roadmap choices.
